* `models-as-tools`  What a generative model actually gives you — Session 1. The API surface: prompt in, tokens out, and nothing else; system vs. user vs. assistant roles; context windows and why they are a budget, not a memory; temperature, top-p, and stop sequences as the only real knobs; structured output and function/tool calling as the bridge from text to software; streaming and latency; token-based pricing and how cost is estimated before you ship. Real-world close: why a feature that works in the chat window breaks in production — no conversation state, no retries, no schema — and what an integration layer has to supply.

* `building-with-generation`  Wiring a model into a real system — Session 2. Prompt engineering as engineering: instructions, examples, and output contracts that hold under load; retrieval-augmented generation — chunking, embeddings, vector search, and grounding answers in your own documents; agents and tool use — letting the model call your code, and the loop that results; evaluation — golden sets, LLM-as-judge, and regression testing a nondeterministic component; guardrails — validation, retries, fallbacks, prompt injection, PII, and cost/rate limits; deployment concerns: caching, observability, model version pinning. Real-world close: anatomy of a shipped feature — a support assistant grounded in a help center — traced end to end from user question to validated answer.

* `reasoning-primer-subject`  How to reason about integration cases — the diagnostic primer: given a scenario (a chatbot inventing a refund policy, an agent looping on a tool call, retrieval returning the right document but the wrong passage, costs tripling after a prompt edit), name the concept that explains it and point to the detail in the scene that decides it; resist "the model just needs a better prompt" as a universal answer.

* `reasoning-primer-general`  Core reasoning skills — the five-skill primer (analysis, inference, evaluation, deduction, induction) retargeted to AI systems: analysis separates what the model was given from what it produced; inference distinguishes what an output proves about the system from what it only suggests; evaluation judges whether an eval result actually supports a deployment decision; deduction covers what the architecture guarantees regardless of the model; induction covers generalizing from a handful of test cases and why a demo is not evidence of reliability.
